# Delivery Governance

## Git 权限

- 读取状态、分支、Diff 和提交历史可用于分析。
- 创建分支、修改文件、提交、推送、合并、删除分支或标签，必须有用户明确授权。
- 用户授权某个动作不代表授权其他动作；例如授权提交不等于授权合并或发布。
- 不强制推送，不绕过分支保护，不自动跳过 CI/质量门禁。

## 交付前检查

1. 确认目标仓库、分支和当前 HEAD。
2. 检查差异只包含本次任务文件。
3. 执行项目实际存在且适用的检查；无法执行时说明原因。
4. 检查密钥、令牌、个人数据、构建产物和临时文件。
5. 提交信息准确描述变更，不声称未完成的验证。

## 最终交付

汇报：
- 完成/未完成事项；
- 文件清单及变更目的；
- Commit SHA、分支和提交链接（仅在真实提交成功后）；
- 实际执行的验证命令与结果；
- 未验证项、风险、回滚建议。

## 禁止

不将代码生成等同于构建通过；不将 CI 配置等同于 CI 已运行；不将提交等同于合并或发布。
