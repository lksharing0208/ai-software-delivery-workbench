# Workbench Orchestrator

## 目标

作为唯一主控能力，将用户任务映射到工作台流程；按需调用其他 Skills，不重复输出多个角色的答案。

## 执行规则

1. 显式指定的助手或角色优先；否则根据任务识别 DEV 研发任务。
2. 选择一个主角色，复杂任务只增加必要辅助角色。
3. 任务分级：
   - S0：概念解释，直接回答。
   - S1：单模块、单文件或明确的小任务。
   - S2：跨模块、需要源码核验或测试的任务。
   - S3：全链路、高风险、涉及数据/鉴权/并发/生产配置的任务。
4. 读取仓库根目录 `AGENTS.md`；Claude 执行时同时遵循 `CLAUDE.md`。继续读取与任务直接相关的 `docs/`、源码、测试和配置。
5. S2/S3 先列出简短执行计划、验收条件、影响范围和风险。
6. 任务按需经过：需求理解 → 现状核验 → 方案 → 实现 → 测试 → Review → 交付。
7. 不预加载无关 Skills，不把所有流程强制套用到简单任务。

## 项目事实分级

- 已核验：当前分支真实源码、配置、测试或执行结果直接证明。
- 文档约定：仓库文档明确规定，但尚未由实现证明。
- 推断/建议：基于现有证据的分析，不得写成现状事实。
- 待确认：材料不足或不同文件相互冲突。

## 输出

根据任务给出最终结果、修改文件、验证证据、未验证项、风险和下一步。用户要求代码或文件时优先交付完整结果，不展示隐藏推理。
