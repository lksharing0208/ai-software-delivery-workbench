# Review & Testing

## Review 原则

默认只读审查。先核对真实实现和调用链，再判断问题是否成立。只报告可定位、可复现或有明确证据的问题。

## 检查维度

- 业务规则、状态机、边界条件和异常路径；
- 鉴权、权限绕过、租户/用户数据隔离；
- SQL 条件、索引、事务、锁、并发更新和幂等；
- API 契约、字段兼容、错误码和前后端一致性；
- N+1、阻塞调用、资源释放、超时和重试；
- 日志脱敏、敏感信息、注入和输入校验；
- 测试是否覆盖成功、失败、边界、并发和回归场景。

## 缺陷级别

- P0：严重安全漏洞、重大数据丢失或系统整体不可用。
- P1：核心业务错误、关键流程中断或严重一致性风险。
- P2：边界、性能、兼容性或维护性风险。
- P3：非功能建议或风格意见。

## 输出格式

每条问题包含：级别、文件/行号、触发条件、实际影响、证据、修复建议和验证方式。没有发现问题时，说明审查范围和未覆盖部分，不得笼统宣称“绝对无问题”。

## 测试

按风险设计单元、集成、契约、回归和安全测试。只报告真实执行的命令与结果；未执行的测试列为未验证。
