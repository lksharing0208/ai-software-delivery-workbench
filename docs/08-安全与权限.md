# 08｜安全、数据和权限基线

## 一、模型和仓库授权

- 网页模型只授权完成任务所需的仓库和权限范围。
- 不把“允许读取代码”扩大为“允许写入、合并或部署”。
- 对不需要的连接及时撤销授权；以平台当前权限页面为准。
- 私有仓库代码、日志、业务数据被发送给外部模型前，先评估组织政策、合同与数据分类要求。

## 二、秘密管理

禁止提交：

- API 密钥、访问令牌、OAuth 凭据、私钥和证书私钥；
- 数据库账号密码、真实环境连接串和云平台访问密钥；
- 生产环境完整配置或含敏感字段的日志；
- 真实用户身份信息、支付记录或其他受保护数据。

使用 `.env.example` 表达必要配置名称和示例占位值；真实 `.env` 文件应被忽略并只存在于授权环境中。GitHub Actions 使用 Secrets 或 Environment Secrets；部署环境使用组织认可的秘密管理服务。

如果密钥误提交，立即吊销或轮换，再评估历史提交清理与日志调查。单纯删除最新文件不代表密钥已安全。

## 三、最小权限

- CI 默认只读代码权限；没有必要时不授予写入内容、创建发布或管理部署的权限。
- 第三方 Action 和脚本只使用经过审查的版本与来源。
- 生产凭据只向确实需要的部署任务提供，不向普通 PR 测试任务提供。
- 生产发布与数据迁移采用人工审批或组织批准的控制机制。

## 四、AI 生成代码风险

AI 输出必须视作待验证的代码。对来自模型的依赖、命令、SQL、网络调用、文件系统操作、权限调整和迁移脚本，先核对来源与副作用，再运行。

禁止在没有人工审查的情况下直接执行模型生成的破坏性命令、生产 SQL 或部署脚本。不要让模型为通过测试而禁用安全校验或降低权限约束。

## 五、审计记录

记录任务编号、修改提交、Review 决策、CI 结果、合并人、部署人、生产验证和回滚事件。记录中只保留调查所需的最少信息，避免复制敏感数据。
