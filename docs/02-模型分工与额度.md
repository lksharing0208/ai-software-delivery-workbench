# 02｜模型分工、免费额度和任务升级策略

## 一、模型职责

| 模型 | 主职责 | 默认输出 | 默认是否修改项目文件 |
|---|---|---|---|
| Codex + DeepSeek 桌面端 | 主开发者：读本地项目、实现功能、补测试、修复、重构和构建 | 代码差异、测试结果、风险与回滚说明 | 是 |
| ChatGPT 网页端 | 需求分析、系统设计、复杂故障分析、业务规则复核 | 方案、验收条件、独立审查结果 | 否 |
| Claude 网页端 | 独立代码审查，检查副作用、边界、并发、资源与兼容性 | 按严重级别排列的缺陷清单 | 否 |
| Gemini 网页端 | 跨文件理解、测试遗漏、替代方案 | 模块图、边界清单、测试建议 | 否 |
| Grok 网页端 | 最新框架、依赖、发布说明和外部技术事实核查 | 带来源与日期的技术结论 | 否 |

网页端连接 GitHub 只作为代码上下文来源，不应默认它能写回分支。对每个模型，只使用账户中实际启用的连接能力。

## 二、免费网页额度工作量建议

建议先按工作价值分配，而不是追求“每天必须问完四个模型”。可用额度因账户、模型、上下文长度、工具调用和平台策略而变化，以下是相对工作量建议，不代表具体消息数或平台承诺。

| 模型 | 计划占比 | 用途 |
|---|---:|---|
| ChatGPT | 35% | 需求澄清、架构、复杂问题与验收复核 |
| Claude | 35% | 关键 PR 独立 Review |
| Gemini | 20% | 大范围分析和测试补漏 |
| Grok | 10% | 有时效性的外部技术事实核查 |

## 三、付费编码额度建议

将当前可用月度编码预算按以下目标规划，每周根据真实用量调整：

| 用途 | 目标占比 |
|---|---:|
| 常规编码与功能实现 | 55% |
| 复杂缺陷排查与重构 | 25% |
| 疑难验证与测试修复 | 15% |
| 预留 | 5% |

不需要将该比例配置成自动硬限制；它是成本管理目标。需要分别核对 Codex 账户权益、DeepSeek API 或其他调用渠道的实际计费方式，不能混为一个额度池。

## 四、什么任务需要多模型

### 普通低风险任务

例如文案、局部校验、简单查询、独立测试补充：

1. Codex + DeepSeek 实现。
2. 本地执行测试、构建和差异检查。
3. 使用 ChatGPT 或 Claude 中的一个进行 Review。
4. 处理真实缺陷后提交 PR。

### 高风险任务

涉及支付、权限、并发、数据库迁移、敏感数据、核心架构、生产部署时：

1. ChatGPT 帮助明确需求、边界和验收条件。
2. Codex + DeepSeek 在独立分支实现。
3. Claude 独立审查，优先给出证据而不是直接重写代码。
4. ChatGPT 或 Gemini 从不同角度复核高风险点。
5. 运行自动化测试与必要的集成/回归测试。
6. 人工审批后才能合并和发布。

### 何时使用 Grok

仅在需要确认“最新版本、近期变更、刚发布功能、某种兼容性是否仍成立”等外部事实时使用。优先引用官方文档和发布公告，记录核查日期；不要把未经证实的论坛观点作为确定事实。

## 五、是否新增 Claude 付费本地编码工具

暂不建议仅为了增加一个模型就开通新订阅。先使用 Claude 网页端做独立 Review，并观察一个完整开发周期。如果现有 Codex + DeepSeek 无法稳定解决复杂问题、确实需要第二个本地执行环境或经常因额度限制中断，再评估第二套本地代码代理。

若引入第二套本地工具：

- 使用单独 Git Worktree 或功能分支。
- 不允许两套代理同时修改同一工作区的同一批文件。
- 通过独立差异、测试和 Review 决定是否采纳。
- 比较真实月费、解决问题的成功率、返工率和耗时，而不是比较模型数量。

## 六、通用额度节约办法

- 先提供相关文件、调用链和精确问题，不要每轮都发送整个仓库。
- 将稳定规范写入 `AGENTS.md`、`CLAUDE.md` 与架构文档。
- Review 聚焦 Git 差异；不要要求模型重复描述未修改的文件。
- 先让模型列问题和证据，再让主执行者实施；减少“发现问题—整段重写—又推翻”的循环。
- 简单任务只启用一个审查模型；高风险任务才采用双重审查。
- 每周记录调用费用、有效缺陷数、返工次数和任务耗时。
