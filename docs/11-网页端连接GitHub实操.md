# 11｜网页端模型连接 GitHub 的实操步骤与限制

> 本文按 2026-10-19 可查到的官方说明整理。不同账户、套餐、地区和组织策略可能导致界面或可用能力不同；请以当前登录账户的实际界面为准。

## 一、先区分四种能力

连接 GitHub 不等于自动获得所有权限。请分别验证：

1. **读取代码**：能否选择仓库/分支并读取具体文件。
2. **读取变更**：能否读取 PR 差异、提交号和最新修改。
3. **写入代码**：能否创建或修改文件、提交分支、创建 PR。
4. **运行与部署**：能否执行构建/测试，以及是否拥有部署权限。

本工作台的默认设计是：网页端主要提供需求分析和独立 Review；Codex + DeepSeek 负责在本地改文件、运行命令与准备提交。除非实际验证了额外权限，不应把网页连接当成自动写回仓库的执行环境。

## 二、ChatGPT 网页端

官方入口：<https://help.openai.com/zh-hans-cn/articles/11145903-connecting-github-to-chatgpt>

推荐操作：

1. 在 ChatGPT 中打开设置，找到“应用”或“连接器”相关页面（名称可能随界面变化）。
2. 找到 GitHub 并选择连接。
3. 根据提示跳转至 GitHub 授权。
4. 选择允许访问的仓库范围，优先只开放工作流模板仓库和当前需要审查的业务仓库。
5. 回到 ChatGPT，在新对话中明确要求检索指定仓库内的文件、路径或实现；给出目标分支和提交号。
6. 要求模型在回答中说明实际读取的文件和无法访问的内容。

注意：官方说明指出，该连接用于按需检索已授权仓库内容，不等于实时同步索引。对当前 PR 做 Review 时，最好提供 PR 链接、提交号和差异；若模型拿到的内容不完整或版本不一致，需补充最新 patch。不要依赖 ChatGPT 网页 GitHub 连接直接提交代码；写入仍由本地 Git/Codex 工作流完成。

## 三、Claude 网页端

官方入口：<https://support.anthropic.com/en/articles/10167454-using-the-github-integration>

推荐操作：

1. 在 Claude 网页端新建对话，点击输入框附近的添加按钮。
2. 选择“从 GitHub 添加”一类选项，并按提示完成 GitHub 身份认证。
3. 从文件浏览器中选择需要审查的仓库、文件或目录；也可在 Claude Project 的知识区添加 GitHub 内容。
4. 在提示词中明确指定 PR、提交号、审查范围和需要输出的格式。
5. 对关键 Review，确认所引用的内容对应最新分支/提交；如果存在不确定性，再提供最新差异文本。

默认定位为只读分析和独立审查。不要假设网页端可以写入文件、推送分支或部署；本工作台将所有实际修改交给桌面端主执行者。

## 四、Gemini 网页端

官方入口：<https://support.google.com/gemini/answer/16176929?hl=zh-Hans>

推荐操作：

1. 在电脑浏览器打开 Gemini 网页端。
2. 点击输入框中的“添加文件”，进入“更多上传”或“导入代码”。
3. 选择 GitHub 仓库或分支 URL，按照页面提示完成导入/关联。
4. 私有仓库需要当前 GitHub 账户具备访问权限，并按界面提示关联账户。
5. 导入后再提出跨文件分析、测试补充或指定函数分析任务。

关键限制：官方帮助说明，导入后的仓库不会自动同步后续提交；一个对话可导入的仓库文件数和大小也有限制，而且 GitHub 应用不能写回仓库、检索提交历史或 PR 元数据。因此每次审查必须重新导入对应版本，不能把旧聊天中的代码快照当成最新实现。

## 五、Grok 网页端

本工作台不依赖 Grok 的仓库写入能力，也不假设其账户一定提供 GitHub 私有仓库集成。建议仅把 Grok 用于最新技术资料核查：

1. 搜索官方文档、官方发行说明和安全公告。
2. 对公开仓库可提供精确文件链接、版本号或提交号作为上下文。
3. 对私有仓库，只有在组织政策允许时，才提供经过筛选和脱敏的最小差异片段；不要把私有代码整库公开。
4. 要求输出来源 URL、发布/更新日期、适用版本和未确认事项。
5. Grok 给出的建议应回到项目源码、官方文档和实际测试验证后再采纳。

## 六、所有模型通用的连接验收

每个模型首次连接后，执行一次以下验收：

- [ ] 能读取目标仓库中的 `README.md`。
- [ ] 能读取 `AGENTS.md` 或相关规范文件（如果支持选择该文件）。
- [ ] 能按指定路径分析一个具体文件。
- [ ] 能明确指出当前资料是否为最新提交。
- [ ] 不要求模型输出或展示密钥、用户隐私等敏感内容。
- [ ] 已确认该连接究竟是只读、可写还是可执行，不靠猜测。

如果模型不能直接访问 PR 或代码仓库，应改用其支持的方式提供精简 diff、文件片段和测试结果；不得为了实现“连接”而公开私有仓库。

## 七、建议的日常输入格式

```text
仓库：<仓库地址或已授权仓库名称>
目标分支：main
审查提交：<完整提交号>
PR：<链接，如有>
任务：请基于本次差异进行独立代码审查，不要直接重写整份文件。
需要重点检查：业务正确性、异常路径、接口兼容、权限、安全、并发、测试遗漏、迁移与回滚。
请列出实际读取的文件；无法读取或无法确认版本的部分必须明确说明。
输出：按 P0/P1/P2/P3 排序的问题、文件与行号、触发条件、影响、证据、修复建议和验证办法。
```
