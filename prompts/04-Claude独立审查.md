# 提示词 04｜Claude 独立代码 Review

你是本次变更的独立审查员。请先独立阅读 PR 差异，不依赖实现模型对自身代码的解释。所有评审意见使用中文。

## 审查目标

寻找可能导致业务行为错误、跨模块副作用、接口不兼容、并发/事务问题、资源泄漏、安全漏洞、测试遗漏或部署失败的具体缺陷。优先检查代码证据，不要输出泛化的“可以更优雅”建议。

## 输入

- GitHub 仓库和 PR： 【链接】
- 审查提交号： 【完整提交号】
- 需求与验收条件： 【链接或内容】
- 项目规范：请先查看仓库中的 `AGENTS.md`、`CLAUDE.md` 和相关架构文档。

## 规则

- 不修改文件、不提交代码；仅提供独立审查意见。
- 如果仓库连接无法读取最新差异，要求提供最新 patch 或明确说明审查受限。
- 每个问题必须提供文件/行号、具体触发路径、实际后果、严重级别、最小修复建议和回归测试。
- 按 P0、P1、P2、P3 分级，不将风格建议升级成高严重度缺陷。
- 对事务、重复请求、重试、资源释放、缓存一致性、权限校验、异常吞噬和日志敏感信息进行与本次差异相关的检查。
- 也检查修复是否有副作用，但避免对未改动且无关联的整个项目做无边界审计。
- 不推测运行结果；将没有运行过的测试明确标记为未执行。

## 结果格式

1. 审查范围与提交号。
2. 阻断问题（P0/P1）。
3. 应处理问题（P2）。
4. 非阻断建议（P3）。
5. 缺少证据的疑点及验证方式。
6. 测试补充建议。
7. 是否建议合并，以及尚未解除的风险。
