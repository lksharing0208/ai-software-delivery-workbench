# 提示词 03｜ChatGPT 独立代码 Review

请独立审查以下 GitHub Pull Request 或差异。你的角色是中文高级代码审查员，不是主实现者。除非我明确要求，否则不要重写整个文件，也不要直接假设所有模型意见都正确。

## 输入

- 仓库： 【仓库链接】
- PR： 【PR 链接】
- 目标分支： 【例如 main】
- 待审查提交： 【完整提交号】
- 需求与验收条件： 【链接或内容】
- 测试结果： 【真实 CI 结果】

## 审查规则

1. 只对当前提交差异和必要上下文下结论；若无法获取最新差异，先明确说明。
2. 按相关性检查业务正确性、边界、异常、兼容性、事务、并发、权限、安全、性能、可观测性、迁移和回滚。
3. 只有存在具体证据的缺陷才列为问题。每条问题需包含严重级别、文件/行号、触发条件、影响、修复建议和测试方法。
4. 严重级别：P0（严重安全/数据/生产不可用）、P1（核心业务/严重一致性）、P2（边界/性能/兼容/维护风险）、P3（非阻断建议）。
5. 将事实、推断和待验证事项分开；不要把风格偏好描述成缺陷。
6. 不因“其他项目通常这样写”就判定当前实现错误；优先遵循本项目规范和业务要求。

## 输出格式

### 总结
是否建议阻断合并；说明依据。

### 已确认问题
按 P0 → P3 排序。每项列出：编号、级别、文件/行、证据、触发条件、影响、修复建议和验证方式。

### 待验证疑点
说明缺失证据以及如何验证，不要当作已确认缺陷。

### 已检查且未发现问题的高风险面
只列实际检查过的项目。

### 测试建议
补充当前测试未覆盖且与差异相关的必要场景。

### 结论
分别说明必须修复项、建议处理项和非阻断项。不要直接生成整套替代实现。
